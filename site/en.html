PROVIDERS · GATEWAY AND DIRECT

Providers, your call

The gateway gives every agent one shared provider pool; Codex's original direct modes still work, and you can switch at any time.

Gateway

One local gateway serves Codex, Claude Code, and Grok from a shared provider pool. Requests are routed by model name, keys rotate and cool down, and errors move on to the next provider. Subscriptions such as ChatGPT, GitHub Copilot, and SuperGrok can be signed in to the pool.

  • One provider pool for every agent
  • Route by model name, provider, or group
  • Multi-key rotation, cooldown, and circuit breaking
  • Usage and cost per agent, provider, and model
Agents Codex++ Provider pool

One suffix, a million tokens

In the gateway, set windows per model in the provider details (one click fills them from public data). In direct mode, write a window suffix in the model list and Codex++ generates a dedicated model_catalog_json so Codex uses the right window per model. Models without a suffix keep provider-level settings.

GETTING STARTED

Three steps, done

Codex features work alongside the official Codex / ChatGPT desktop app; Claude and Grok features need their own clients installed.

01

Install and add providers

From GitHub Releases: Windows picks *-windows-x64-setup.exe, macOS picks *-macos-universal.dmg. In the Provider pool, paste an API key, sign in to a subscription, or import from direct mode.

→
02

Connect your agents

Under Agent access, switch on Codex, Claude Code, or Grok and pick a default model. Config files are backed up first, and disconnecting restores only what the gateway changed.

→
03

Launch Codex

Click "Launch Codex" or the ▶ next to Codex in the sidebar to inject enhancements; Claude Code and Grok keep working in your terminal. Injection-based settings apply after a Codex restart.

Prefer not to use the gateway? Direct mode still works: pick a provider under Codex → Provider configuration (legacy) and launch. Every enhancement can be toggled individually.

FAQ

Asked, answered

Why is there no Codex++ menu after launch?

Make sure you launched the official app from the Codex++ manager with the "Launch Codex" button. Check the app path, launch status and diagnostic logs under Codex → Settings (maintenance is at the bottom) and the About page. On macOS you can also turn on "Auto-takeover of the official app" so Codex++ takes over when you open the official app yourself.

Why do requests fail after switching providers?

In gateway mode, click "Test" in the provider details to see the status code, time to first token, and the upstream error text; failed requests under Usage → Requests show their reason too. In direct mode, run a model test or Provider Doctor in the provider details. API-only and official+API modes store credentials differently — don't hand-copy auth.json between them.

Why can't my agents connect after I quit Codex++?

Agents connected to the gateway keep pointing at the local gateway, which only runs while Codex++ is open; reopening Codex++ restores them. To fall back to direct connections on exit, turn on "Restore direct connections when Codex++ exits" in Gateway settings (off by default). Codex++ always switches back to direct mode before installing an update.

Why is the native Fast switch still missing?

Confirm that you saved and restarted Codex through Codex++. In direct mode, open the model's settings under Codex → Provider configuration (legacy), set “Fast (priority) support”, then save both the model and provider before restarting. In gateway mode, a model group supports Fast when every member does. Only declare support that your provider actually offers; unlocking the client control does not change service limits or billing.

Computer Use tools don't show up in my client

Restart the client after connecting. Fully quit Claude Desktop first, because it rewrites its own config on exit. If the tools are still missing, check the config directory the client actually reads under “Config paths and custom directories” on the Computer Use page, and make sure ChatGPT has Accessibility and Screen Recording permissions. macOS only for now.

Can enhancements be disabled? Will they survive official app updates?

Yes — individually or via the master switch. Codex++ depends on the official app's page structure, CDP and local data formats, so some features may need follow-up adaptations after official updates. Back up before changing provider settings or session data.

Where are config, sessions and logs stored?

CODEX_HOME wins when set; otherwise ~/.codex. API keys never leave your machine — redact secrets before submitting feedback.
