Extensions

Not just the UI, the whole pipeline

An extension is a folder with a codexpp.json. Every registration is undone automatically when it unloads, edits hot-reload, and a broken extension never takes others down.

Modes

Gateway or direct, switch any time

The two modes are independent; Codex switches between them with one click under Connection at the top of Connection & providers. Leave the gateway off and Codex++ works just like 1.x.

Recommended

Gateway mode

Codex, Claude Code, and Grok share one provider pool.

  • Route by model name, provider, or group, failing over on errors
  • Sign subscriptions in to the pool and see plan and quota
  • Agent configs are backed up first; disconnecting restores only gateway changes
  • Usage and cost by agent, provider, and model

Best for: several agents, several providers, or several keys. The gateway is available while Codex++ is running.

Direct mode

Codex's original provider switching, fully preserved.

Official loginOfficial + APIAPI onlyFailoverModel aggregation
  • Official + API keeps sign-in and plugins while requests use a compatible API
  • Chat Completions providers are converted locally to Responses for Codex
  • Codex multi-launch, model tests, and Provider Doctor

Best for: Codex only, or configs that keep working after Codex++ quits. Pick a provider under Codex → Connection & providers.

One suffix, a million tokens

Each model can have its own context window. In the gateway, set it per model in the provider details (one click fills it from public data). In direct mode, add a suffix in the model list and Codex++ generates a dedicated model_catalog_json so Codex uses the right window per model.

Get started

Three steps, connected

Codex features work with the official Codex / ChatGPT desktop app; Claude and Grok features need their own clients installed.

  1. Add providers

    Open Gateway → Provider pool: paste an API key, sign in to a ChatGPT / Copilot / SuperGrok subscription, or import several from direct mode or OpenCode. Models and prices fill in automatically.

  2. Connect agents

    Under Gateway → Agent access, switch on Codex, Claude Code, or Grok and pick a default model. Claude Code and Grok keep working in your terminal.

  3. Launch Codex

    Click Launch Codex or the start button next to Codex in the sidebar to inject enhancements. Injection-based settings apply after restarting Codex from Codex++.

FAQ

Asked, answered

Is it safe to install other people's extensions?

Featured and official extensions are reviewed by Codex++ and install the exact reviewed commit. Community extensions are not reviewed and authors can add any code in a new version: before install you see every capability they declare (background processes, hooks, gateway middleware, model tools, routes, page scripts), and installs start disabled. Only install extensions from authors you trust.

How do I start building by chatting? What if it breaks?

On the manager's Extensions page, click Connect to Codex under build by chatting, then start a new Codex chat and describe what you want. Extensions are written to your own extensions folder, and writes go through Codex's tool approval. A failing extension only affects itself: disable it under Local extensions or ask the agent to fix it.

Why is there no Codex++ menu after launch?

Enhancements are only attached to an official app launched from Codex++. If you opened Codex yourself, the Codex row in the sidebar says it is not attached and its button becomes "Restart & attach"; click it. If the menu is still missing, check the app path, launch status and diagnostic logs under Settings → Codex (which includes install & maintenance) and Settings → Logs & Diagnostics. On macOS you can also turn on "Auto-takeover of the official app" so Codex++ takes over when you open the official app yourself.

Why do requests fail after switching providers?

In gateway mode, click "Test" in the provider details to see the status code, time to first token, and the upstream error text; failed requests under Usage → Requests show their reason too. In direct mode, run a model test or Provider Doctor in the provider details. API-only and official+API modes store credentials differently — don't hand-copy auth.json between them.

Why can't my agents connect after I quit Codex++?

Agents connected to the gateway keep pointing at the local gateway, which only runs while Codex++ is open; reopening Codex++ restores them. To fall back to direct connections on exit, turn on "Restore direct connections when Codex++ exits" under Settings → Gateway (off by default). Codex++ always switches back to direct mode before installing an update.

Why is the native Fast switch still missing?

Confirm that you saved and restarted Codex through Codex++. In direct mode, open the model's settings under Codex → Connection & providers, set “Fast (priority) support”, then save both the model and provider before restarting. In gateway mode, a model group supports Fast when every member does. Only declare support that your provider actually offers; unlocking the client control does not change service limits or billing.

Computer Use tools don't show up in my client

Restart the client after connecting. Fully quit Claude Desktop first, because it rewrites its own config on exit. If the tools are still missing, check the config directory the client actually reads in the “Advanced” card on the Computer Use page, and make sure ChatGPT has Accessibility and Screen Recording permissions. macOS only for now.

Can enhancements be disabled? Will they survive official app updates?

Yes — individually or via the master switch. Codex++ depends on the official app's page structure, CDP and local data formats, so some features may need follow-up adaptations after official updates. Back up before changing provider settings or session data.

Where are config, sessions and logs stored?

CODEX_HOME wins when set; otherwise ~/.codex. API keys never leave your machine — redact secrets before submitting feedback.
