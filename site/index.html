Codex · Build by chatting

说一句话，拓展就写好了

不用自己写代码。接入后，Codex 能看到自己的页面结构、写出拓展、热重载，再截图确认效果。

  1. 在「拓展」页点「接入 Codex」Codex 多一个本机 MCP 服务，能查看页面结构、截图、写入并热重载拓展。
  2. 新开对话，直接说需求比如 把发送按钮改成🐶狗头、把上下文圆环改成彩虹进度条。说「插件」也行。

Claude · 完整功能模式

完整功能模式：在本机给 Claude 当服务端

常见的接入办法只给 Claude Code 改一个 ANTHROPIC_BASE_URL，或把 Claude Desktop 切到官方的 3p（第三方推理）部署：模型换成了你的，界面和功能却跟着缩水。Codex++ 的「完整功能模式」换了个思路——在本机给原版 Claude Desktop 当服务端：界面是 claude.ai 的完整版，账号、套餐和功能开关由本地服务应答，回复走你的 Codex++ 供应商池。

完整界面，不用账号

项目、Artifacts、定时任务、自定义都在；显示名和套餐（Free / Pro / Max / Ultra）自己定，只影响界面显示。

模型来自你的供应商池

模型选择器里直接列出池里的模型，显示友好名和供应商；按模型名路由、多 Key 轮换、出错换下一家。

听写、电脑控制、后台模式

本地 SenseVoice 听写，结果只进输入框、不自动发送；Computer Use 入口与后台模式可用。

每个模型，各自的窗口

网关为每个模型声明的上下文窗口写进 Claude 的设置，切换模型不必重启，不再一律按 200k 算。

Get started

三步，接上就用

Codex 功能配合官方 Codex / ChatGPT 桌面应用使用；Claude、Grok 相关功能需安装对应客户端。想用 Claude 完整功能模式，看 上面的三步。

  1. 添加供应商

    打开「网关 → 供应商池」：填 API Key、登录 ChatGPT / Copilot / SuperGrok 订阅，或从直连模式、OpenCode 一次导入多家。模型列表和价格自动填好。

    在「网关 → Agent 接入」给 Codex、Claude Code、Grok 打开开关，选默认模型。Claude Code、Grok 接入后照常在终端里用。

  3. 启动 Codex

    点「启动 Codex」或侧栏 Codex 行的启动按钮，增强随之注入。依赖注入的设置改完后，从 Codex++ 重启 Codex 生效。

Codex

装别人的拓展安全吗？

精选与官方拓展经 Codex++ 审核，安装锁定到审核过的那次提交。社区拓展未经审核，作者可以在新版本里加入任意代码：安装前会列出它声明的全部能力（后台进程、钩子、网关中间件、模型工具、路由、页面脚本），装完默认不启用，请只安装你信任的作者的拓展。

对话造拓展怎么开始？写坏了怎么办？

在管理器「拓展」页的「对话造拓展」点「接入 Codex」，然后新开一个 Codex 对话说需求。拓展写在你自己的拓展目录里，每次写入都走 Codex 的工具审批；拓展出错只影响它自己，可以在「本地拓展」里停用，或让 agent 接着改。

启动后，为什么没有 Codex++ 菜单？

增强脚本只挂载到从 Codex++ 启动的官方应用上。自己打开的 Codex，侧栏 Codex 行会提示「未挂载」，它的按钮变成「重启并挂载」，点一下即可。仍然没有时，到「设置 → Codex」（含安装维护）和「设置 → 日志与诊断」检查应用路径、启动状态和诊断日志。macOS 上也可以打开「自动接管官方 App」，自己双击启动官方 App 时由 Codex++ 接管。

开启原生 Fast 后，为什么仍然看不到开关？

先确认已经保存，并通过 Codex++ 重启 Codex。直连模式在「Codex → 连接与供应商」中打开该模型的配置，设置「Fast（priority）支持」，保存模型与供应商后重启；网关模式下模型组里每个成员都支持 Fast 时，选这个组也能开 Fast。此功能只恢复客户端入口，服务限制与计费仍以供应商为准。

增强功能可以关闭吗？官方应用更新后还能用吗？

可以分别关闭，也可以关闭增强总开关。Codex++ 依赖官方桌面应用的页面结构、CDP 和本地数据格式；官方应用更新后，部分功能可能需要跟随适配。修改供应商配置或会话数据前，请保留备份。

Claude

Claude 完整功能模式和别的工具接 Claude 有什么不一样？

多数工具只改 Claude Code 的 Base URL，或者让 Claude Desktop 用官方的 3p 部署，后者界面是第三方推理版，Computer Use 等远端功能开关也会被过滤。完整功能模式由 Codex++ 在本机应答 claude.ai 的账号与功能接口，界面是完整版，回复走你的供应商池，所以听写、Computer Use、后台模式这些入口都能用，而且不需要登录 Claude 账号。

完整功能模式需要什么条件？

目前仅支持 macOS，需要装好 Claude Desktop 和 Node.js。在「网关 → Agent 接入」给 Claude Desktop 选默认模型，再到「Claude → Desktop 增强」把启动模式切到「完整功能模式」，准备并信任本机证书。启动前先完全退出 Claude，再从 Codex++ 启动；已经打开的 Claude 不会自动接上。

要信任的本机证书安全吗？能撤销吗？

证书和私钥由 Codex++ 在本机生成，放在它自己的状态目录里，只用于本地服务应答发往 claude.ai 的请求；只有从 Codex++ 启动、指向本地服务的 Claude 才会经过它。不用时在同一页点「取消信任证书」即可从钥匙串移除；切回 3p 模式时，Codex++ 会还原它改过的 Claude 部署配置。

网关与通用

切换供应商后，请求为什么失败？

网关模式先在供应商池详情里点「测试」，看状态码、首字耗时和上游错误原文；「用量 → 请求」里失败的请求也会直接显示原因。直连模式在供应商详情中运行模型测试或 Provider Doctor；纯 API 和官方登录 + API 使用不同的认证位置，不要手工复制两种模式的 auth.json。

退出 Codex++ 后，Agent 为什么连不上？

接入网关的 Agent 一直指着本机网关，网关只在 Codex++ 运行时可用，再打开 Codex++ 就恢复。想在退出后用回直连，可在「设置 → 网关」里打开「退出 Codex++ 时恢复直连」（默认关闭）；安装更新前总会先切回直连。

Computer Use 接入后，客户端里为什么没有工具？

接入后需要重启对应客户端才会加载工具；Claude Desktop 退出时会重写自己的配置，建议先完全退出再接入。仍然没有时，在「Computer Use」页的「高级」卡里核对客户端实际读取的目录，并确认已给 ChatGPT 授予辅助功能与屏幕录制权限。目前仅支持 macOS。

配置、会话和日志存在哪里？

设置了 CODEX_HOME 时，Codex 主目录以该变量为准；否则使用 ~/.codex。Codex++ 的状态与日志在 ~/.codex-session-delete/。API Key 只保存在本机，提交反馈前请隐藏密钥与认证信息。
