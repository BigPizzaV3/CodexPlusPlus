## 受控兼容与诊断

### 严格 Responses 推理历史

#1851 / #2067 / #2047 的完整跨供应商、跨账号续聊尚不能宣称解决。新增默认关闭的“严格 Responses 推理历史兼容”，只用于用户已确认目标上游接受同一账号加密历史的场景。

开启后，混合明文与密文的 reasoning 项只在信封格式可识别时生成加密优先的出站投影，本地 rollout 不变。占位 UUID、无法识别的密文明确返回 `incompatible_reasoning_history`，不会先丢掉唯一可读内容再发请求。格式检查不等于密码学认证或解密；这些仍由上游完成，失败不伪造成功、不自动重放工具。

实际回环测试确认：默认保持原样；占位密文的错误不包含正文、没有发出上游请求；可识别信封只改变出站副本，原始输入保持不变。

### MCP 启动路径

#2583 新增“检查启动路径”，后台执行且有三秒响应时限。检查不启动命令、不写配置、不重启服务器。

仅当 WindowsApps 路径匹配已知官方包名、publisher 和固定 CLI 布局，且使用 `mcp-server` 时，可从桌面版当前维护的 CLI 找到替代文件，用户可将其放入草稿后自行保存。普通 PATH 命令、未知包运行时和无参数的 `ChatGPT.exe` 明确区分，不只替换版本号。

原报告 `cua_repl / stdio / ChatGPT.exe / 无 args` 仍缺真实插件运行时清单，不能据此自动生成 Node/worker/环境映射。其他 publisher、同名程序和逃逸布局不会被识别为可替换的 CLI。文件存在也不代表 MCP 握手或工具就绪；完整 CUA 入口恢复仍需提供相应清单的脱敏结构。

## 默认行为与设置安全

- 新的 Lite 信任和严格历史开关默认关闭，旧配置不增加这些序列化字段。
- 两个字段纳入设置保留逻辑的已知字段，关闭后不会被旧 JSON 中的 `true` 复活；保存、重读、磁盘字段均有回归。
- 思考参数规则按供应商、模型生效，默认自动兼容；同一供应商的其他模型保持原请求。
- 新增 MCP 检查仅注册为管理器 Tauri 命令，不进入第三方扩展路由白名单；已发布扩展类名和 constants 未改名。

## 固定实例重启

验收进程发现，旧脚本将包含 `Codex++.app` 的路径直接作为 `pkill/pgrep` 正则，导致 `+` 未转义而未结束旧实例。已统一转义路径，只匹配固定 bundle 的进程；旧实例无法退出时终止替换，避免误报新版本已运行。回归覆盖带 `+`、`[]` 的路径，并排除正式安装与相似名称。交付前另外核对二进制时间、进程启动时间与严格签名。
