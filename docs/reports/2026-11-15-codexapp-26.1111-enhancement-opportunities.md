## 3. 我们现有实现的缺口

### 3.1 Statsig 覆盖层只覆盖了一半

`34-statsig-overrides.js` 现在包的是 `client.checkGate` 和 `client.getDynamicConfig`。
但 Statsig 客户端的实现是：

```js
checkGate(e, t) { return this.getFeatureGate(e, t).value }
getFeatureGate = this._memoize(..., this._getFeatureGateImpl.bind(this))
```

也就是说 **`checkGate` 只是 `getFeatureGate` 的薄包装**。页面里用 `useGateValue` 的地方会走 `checkGate`，所以现有覆盖对 UI 闸门有效；但新版执行配置直接读：

```js
e.getFeatureGate("2120612410", ...).value        // 消息队列
e.getFeatureGate("1079089693", ...).value        // 时间线
e.getExperiment("3359351081").get("enabled")     // 延迟工具输出
e.getLayer("1574672957").get(...)                // 自定义指令
```

这些**完全绕过我们的补丁**。要真正解锁这些功能，必须同时包：

- `getFeatureGate(name)` → 返回带被改写 `value` 的同形对象；
- `getExperiment(name)` → 返回带 `.get()` 与 `__evaluation` 的同形对象；
- `getLayer(name)` → 返回带 `.get()` 的对象；
- `getParameterStore`（可选）。

这是一个确定的、可测试的缺口。

## 4. 增强候选（按落地顺序）

### 4.1 Feature Lab（P0，低难度）

**做什么**：在 Codex 设置页加一个「实验室」分区，列出原生 feature：

- 名称、stage（beta / underDevelopment / stable / deprecated / removed）、默认值、当前值、说明；
- 搜索、按 stage 过滤、风险标记；
- 一键开关（`experimentalFeature/enablement/set`）；
- 「重启后生效」提示、一键恢复默认、改动前备份 config.toml。

**依据**：

- 原生设置里已有「Experimental features (beta)」，但只显示 `stage === "beta"`，并明确排除了
  `multi_agent`、`plugins`、`remote_control`、`realtime_*`、`chronicle` 等；
- `experimentalFeature/list` 分页返回 `{ data, nextCursor }`，字段含 `name` / `stage` / `defaultEnabled`；
- CLI 0.169 的 flag 注册表已经能看到 `worktrees`、`fast_mode`、`ultrafast_mode`、`gateway_setup_wizard`、
  `realtime_conversation`、`remote_control`、`token_budget`、`context_management`、`rollout_budget`、
  `skill_search`、`plugin_sharing`、`external_migration` 等新条目。

**落点**：Codex 设置页分区（已有 `92-extension-views.js` 的 Codex 设置页分区能力）；
数据走 `codexPlusAppServerClient()`；写开关走原生 RPC，不直接改 config.toml。

**风险**：underDevelopment 里不少会崩会话；必须分级、二次确认、可回滚。

### 4.6 原生网关供应商注册（P1，中，战略价值最高）

**做什么**：把 Codex++ 的本地网关注册成 Codex 原生 `customGateway` provider，而不是只写
`config.toml` 的 `[model_providers.cpx]`：

```js
client.sendRequest("modelProvider/config/write", {
  settings: { type: "customGateway", name, baseUrl, envKey }
});
client.sendRequest("config/value/write", {
  keyPath: "model_provider", value: providerId,
  mergeStrategy: "replace", filePath, expectedVersion
});
```

**依据**：

- 页面里已有 `createCustomGateway({name, baseUrl, envKey})` 与 `setDefaultModelProvider`；
- `ProviderSettingsPatch` 类型含 `customGateway { baseUrl, envKey }`、`bedrock`、`gcp`、`credentialFile`；
- `modelProvider/list` 返回 `defaultProviderId`、`canChangeDefault`、`settings.type`；
- 原生 onboarding 有 `gateway-sign-in-host`（access policy 依赖 `modelProviderSetup`，灰度 `2670279775`）。

**收益**：原生设置里能看到/切换 Codex++ 网关；配置写入原子化；auth 恢复、provider 变更通知
都能复用原生流程；减少我们手写 config.toml 的合并问题。

**风险**：`envKey` 语义、`requires_openai_auth`、gateway OAuth 是否只认 OpenAI 服务端，需要原型验证。
建议先做只读侦察：在注入层调 `modelProvider/list` 和 `config/read`，确认现有 relay 是以什么形态出现的。

## 6. 验证方法（沿用仓库已有约定）

- 注入层能力先用 CDP 在真实页面验证，不要只看正则测试：
  - 独立 `--user-data-dir` 启动，`--remote-debugging-port`；
  - `Page.bringToFront` + `Emulation.setFocusEmulationEnabled`，否则后台页跳过扫描；
  - 注入后轮询 `nav[data-app-navigation-rail]` 再操作。
- 新 RPC 先用 `codexPlusAppServerClient("local").sendRequest(...)` 打一发，确认返回结构；
  再写 UI。
- 版本保护：能力表按 app-server 版本判断（`0.169.0-alpha.11.1` 全支持），
  旧版返回「不支持」而不是崩。
- 配置类改动先备份 config.toml；写开关优先用 `config/batchWrite` / `experimentalFeature/enablement/set`，
  不要再直接改文件（除非任务必需）。

## 附录 A：解包脚本（可复现）

asar 头格式：前 16 字节 = `[4B size][4B headerSize][4B ?][4B jsonSize]`，
JSON 头从 offset 16 开始，**文件数据起点是 `8 + headerSize`**（不是 16 + headerSize，
这里踩过一次 off-by-8，所有文件会少前 8 字节）。

```js
import fs from 'node:fs';
const fd = fs.openSync(asar, 'r');
const h = Buffer.alloc(16); fs.readSync(fd, h, 0, 16, 0);
const headerSize = h.readUInt32LE(4);
const jsonSize = h.readUInt32LE(12);
const jb = Buffer.alloc(jsonSize); fs.readSync(fd, jb, 0, jsonSize, 16);
const header = JSON.parse(jb.toString('utf8'));
const base = 8 + headerSize;
// 递归 header.files；entry.unpacked 的从 app.asar.unpacked 复制，其余读取 base + entry.offset
```
