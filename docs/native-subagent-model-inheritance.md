# 原生子智能体的模型身份继承

Codex 经网关创建的原生子智能体默认继承直接父回合的逻辑模型身份。身份可以是供应商前缀和模型名，也可以是聚合模型标识，例如：

- 父回合使用 `supplier-a/gpt-6.1-sol` 时，子智能体继续使用该完整模型标识。
- 父回合使用 `group/research` 时，子智能体继续使用该组；组内的手动选择、轮换和失败切换仍由网关正常处理。
- 子智能体显式发送其他裸模型名，也不会因此进入整个供应商池重新选择供应商。
- 子智能体主动指定完整的供应商/模型或 `group/...` 组时，保留该选择；后续子智能体以它为父身份。

聚合组本身就是有效模型身份。继承时不会将它替换成某次请求实际选中的供应商或上游模型。

网关通过原生请求中的线程和回合元数据识别直接父回合，将逻辑模型及其路由类型按 Codex Home、SQLite Home、线程及回合持久化。普通请求保持原有模型及路由，同一回合的新请求会更新登记；登记失败记录诊断并放行，不阻断普通请求。模型标识中的 `/` 本身不代表供应商前缀，解析遵循网关现有的模型声明优先规则。

父回合尚未记录时，只从当前 Codex Home 内、原生线程数据库指向的 rollout 中读取对应 `turn_context`；不使用当前全局默认供应商或线程的最新模型代替指定父回合。父回合自身也是子智能体且没有继承记录时，拒绝根据其原始裸模型推断供应商。

普通请求的元数据无效，以及旧版子请求缺少必要父回合标识时，记录诊断并沿用原有路由，此时无法保证继承或避免跨供应商。已识别子请求的身份冲突会失败。明确指定完整模型的子请求也沿用网关原有路由及未知模型策略，调用方应确认该模型可用。身份完整的裸模型子请求若父回合无法核实、身份冲突、路由类型改变或继承模型不可用，则明确失败，不静默切换供应商。父回合本身使用裸模型时，只能继承该裸模型身份，仍由原有路由规则选择供应商。旧登记或原生 rollout 没有保存路由类型时，只能按当前配置解释，不能证明历史类型。

普通请求登记失败时，网关会记录持久故障标记，使此前登记不再用于严格继承；相关父回合须重新成功登记。此前主动指定了不同模型的子回合需再次明确指定其完整模型，才能重新确认自身身份。若故障同时导致登记库和故障标记均无法写入，普通请求仍会放行并记录诊断，但跨进程重启后无法保证识别该次未登记的模型变化。

登记库按最近活动保留 90 天，子回合活动同时刷新已登记的祖先；超过该期限且无活动的记录会定期清理。长时间完全无活动的嵌套子回合恢复后，若无法从父记录可靠恢复身份，则按上述规则失败。SQLite 和 rollout 读取在阻塞任务中执行，不占用 Tokio 工作线程。普通 API 请求及其他 Agent 的网关行为保持原有规则，单独配置的 Codex 起名和自动审批模型也沿用原有规则。

当父模型具有完整供应商或组身份时，原生 `spawn_agent` 工具描述会提示默认继承，并允许主动指定完整模型；网关在请求阶段继续校验实际身份。该策略不会修改原生会话数据库或历史用量。
