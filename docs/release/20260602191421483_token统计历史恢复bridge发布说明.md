# Token Usage History Recovery Bridge Release Notes

Generated: 2026-06-02 19:14

## Summary

This release adds host-side history recovery support for the `Codex Token Usage` plugin. It fixes the case where, after an app restart and with no local cache, the plugin could not restore per-turn call statistics from historical conversations.

## Main Changes

1. Added `thread_usage_history` route support to `BridgeDataService`.
2. Connected local thread history reads in `LauncherDataService`.
3. Added `codex_thread_usage_history` to `SQLiteStorageAdapter`:
   - Reads local `rollout-*.jsonl` files by thread `rollout_path`.
   - Parses `turn_context.turn_id`.
   - Parses `event_msg.token_count.info.last_token_usage`.
   - Preserves `total_token_usage.total_tokens` as `contextUsed`.
4. Added bridge route tests and rollout history parsing tests.

## Effect

- The plugin can request current-session historical call records from the host even when `sessionStorage` and the in-page memory ledger are empty.
- History recovery results can be isolated by:
  - Different conversations in the same project.
  - Different turns in the same conversation.
  - Only the latest turn in the current conversation.

## Validation

Passed:

- `cargo test -p codex-plus-core bridge_routes --manifest-path Cargo.toml`
- `cargo test -p codex-plus-data storage_adapter --manifest-path Cargo.toml`

## Notes

This capability is paired host support for `Codex Token Usage 0.1.6`. If only the script market repository is updated and `CodexPlusPlus` is not updated, history-based statistics recovery after restart will not fully take effect.
