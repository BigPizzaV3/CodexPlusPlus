# 历史会话保留与回收

会话删除首先从列表隐藏，并创建可用于撤销的本地备份。删除状态持久化保存；是否仍被引用由历史依赖关系决定，不以易失的引用计数作为真相。

历史文件按 `history_base` 依赖保留原路径和完整字节。依赖图中的实际分页依赖来自 `history_base`；`forked_from_id` 只表示分叉来源，不作为分页依赖。只要仍有会话引用某段历史，该历史就保留；删除最后一个引用后，管理器才将其标记为可自动回收。

撤销删除会从备份恢复被隐藏的会话及其祖先关系。恢复以持久化的删除状态和 `history_base` 依赖为准，避免仅凭当前列表或缓存判断。

删除界面立即隐藏会话，但 Codex 运行期间可能仍在写入历史文件，因此物理清理延后；Codex 退出后由管理器自动检查并回收已无引用的历史。此流程不承诺硬件、文件系统或外部备份的绝对删除安全。

自动回收移除原生历史文件及对应数据库行，保留删除标记以防索引重建复活。撤销备份单独保留，不随这次回收销毁；撤销叶子会恢复所需的祖先文件，但已删除的祖先继续隐藏。管理器未运行时不执行定期回收，下次启动后重试。

本策略适用于通过 Codex++ 执行的本地删除。依赖元数据损坏或缺失时停止删除；原生写入进程仍运行时只隐藏并保留文件。回收检查与原生进程启动不共享事务，因此不能对外部直接删除文件、磁盘故障或所有跨进程竞态作绝对保证。

多数据库中仍有未标记删除的会话行时，其历史及依赖继续保留，即使另一数据库已经完成软删除。分组撤销先校验全部备份，同路径快照须互为前缀并选择最长版本；全部历史文件落盘后才恢复数据库行。索引恢复失败会返回错误并保留删除状态，修复失败原因后可重试。撤销完成凭据与删除标记在同一数据库事务中更新，以支持跨数据库完成阶段中断后的重试；再次删除会清除旧完成凭据，旧撤销令牌不能覆盖新的删除意图。
