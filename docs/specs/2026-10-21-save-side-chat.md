# 保存 Side Chat 为普通会话

在 Codex++ 设置的「对话与输入」开启「旁支保存」。本地 Side Chat 标签页出现「保存」。按钮在当前回复、工具和审批结束后可用。

管理器入口为「Codex增强 → 常用增强 → 对话与输入 → 旁支保存」，修改后点击「保存增强设置」。管理器和聊天窗口内的开关共用 `codexAppSideChatSave` 配置，默认关闭，受增强总开关控制。

保存内容为创建旁支时的主历史，加上旁支已完成的对话。创建时记录主会话文件的字节截止位置、SHA-256 和可选分叉边界；保存时在后端读取这一段历史。主会话后续新增内容不合入。保存成功后打开普通会话；原旁支没有新增内容时关闭其标签。失败保留原旁支。

新会话按原生分叉规则命名：主会话标题追加 ` (2)`、` (3)`，同一分叉链递增编号，标题含后缀最多 60 字符。使用原生 `setThreadTitle` 同步列表与持久化；主会话没有标题时保留原生默认名称。重试同一次保存沿用首次确定的名称。保存成功提示同时显示该名称。保存按钮与原生关闭按钮保留独立点击区域，避免误触关闭。

按钮只挂在直属包含原生 `[data-app-shell-tab-close-button]` 的标签头。内容区与外层容器即使有相同的 `data-tab-id` 或普通菜单按钮，也不挂载保存入口。按钮悬停提示复用删除、导出按钮的 `installActionButtonEvents`，不使用浏览器的 `title` 提示。点击保存后，按钮显示「保存中」和一个转圈图标并禁用，保留「正在保存」的悬停提示和无障碍标签；失败后恢复为「保存」。转圈图标为按钮内的单个元素，重复扫描不重复添加。操作结果沿用项目已有的 `showToast` 默认样式，与删除、导出一致。

## 实现

- `85-side-chat-save.js`：创建旁支前记录主历史的读取位置和校验值，全文留在后端；保存时从原生会话缓存读取完整旁支记录，不从页面文字拼接。复用原生请求补丁，避免再次包裹客户端原型。
- `side_chat.rs`：保留主历史的原生模型和显示记录，追加旁支对应记录，重新生成连续 ordinal。主会话尚未完成的 turn 和工具调用仅在副本中结束。
- `session_share.rs::write_rollout`：复用导入器的原子写入逻辑，先写完整临时文件，再发布到原生 `sessions/YYYY/MM/DD/rollout-<时间>-<UUID>.jsonl` 路径。新会话使用独立 UUID；相同保存请求可重试，内容不同不覆盖已有文件。
- `session_share.rs::read_rollout`：保存和分享仅共用文件定位、读取。分享仍按原有 16 MiB 上限处理；本地保存不继承分享限制。主历史不通过桥接或 HTTP 请求往返页面，不受这些通道的消息大小限制。
- 原生 `thread/resume` 负责恢复、登记索引和权限。保存接口不直接写 SQLite，不采用旧导入器固定的 `approval_mode=never` 等字段。
- 原生 `thread/read` 核对旁支的 turn、状态和每个显示项后才提示成功。恢复失败再次点击时复用已经写入的文件。
- 保存时读取主会话的项目归属，经原生 `saveThreadProjectAssignment`（旧接口为 `threadWorkspaceStorage.setProjectAssignment`）登记新会话，并校验项目 ID 后才刷新列表、打开新会话和关闭原旁支。不按项目名称或目录推测归属；同名同目录的项目仍按 ID 区分。登记失败保留旁支，重试复用已写文件。

内部路由为 `/side-chat/source`、`/side-chat/save`，不加入第三方拓展路由白名单。功能默认关闭，关闭增强总开关时一起关闭。

## 范围与限制

首版针对本地分页历史的旁支。保存不发送模型请求，不接管后台进程，不重新执行历史工具。

原生临时线程没有历史导出接口。继承主历史是在发出 fork 请求前确定的持久化范围；主会话仍在写入时，它与原生引擎实际复制的瞬间可能存在差异。此功能保存可恢复的历史，不承诺导出临时引擎的全部隐藏状态。主文件后续追加不影响保存；若已记录的前缀被改写或截断，校验失败并保留原旁支。

旁支的用户文字、助手回答、终端和 MCP 工具有对应的原生显示记录。未知展示类型以完整 JSON 历史记录显示，避免静默丢失。无法还原原始调用协议的工具记录，作为明确标记「已经发生」的参考内容提供给模型，不伪造工具调用参数或调用 ID。

首版不支持旁支用户消息中的图片附件，遇到时明确报错，保留原旁支。未完整加载的旁支历史也明确报错，不截断。页面只传旁支记录，仍受现有请求体上限约束；主历史不受该传输限制。

功能开启前创建的旧旁支，仅在主历史此后没有变化时允许保存。无法证明原分叉位置时不读取最新历史冒充旧历史。

保存过程中若旁支又收到新消息，已固定的副本仍可保存，但不关闭有新内容的原旁支。

## 验证

Rust 用合成历史验证主历史保留、工具结果和失败状态、边界、未完成主任务、重试及拒绝不完整数据。另验证超过 16 MiB 的历史可本地保存、分享仍拒绝、后续追加不混入、原前缀改写或截断时拒绝。前端测试验证只传读取引用、原生创建不受采集失败影响、旧大小错误安全恢复、历史完整性、生成时禁用、重复保存与恢复校验。

已使用原生 Codex `0.162.0-alpha.2` 的隔离 App Server 验证：新会话列表可见，主历史和旁支记录完整，工具输出和失败状态保留，进程重启后仍可恢复。测试使用独立 `CODEX_HOME`，不复制凭据，不调用 `turn/start`。

执行原生兼容测试时，设置 `CODEX_PLUS_TEST_CODEX_BIN` 指向本机 Codex 可执行文件，再运行 `cargo test -p codex-plus-core --test side_chat -- --include-ignored`。最终页面点击、重启应用和发新消息由本地实测覆盖。
