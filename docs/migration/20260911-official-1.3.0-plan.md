# Official CodexPlusPlus 1.3.0 Migration

## Baseline

- Branch: `codex/migrate-official-1.3.0`
- Official tag: `v1.3.0`, commit `be6a45852f9992a688f33be933f444ee098fc67a`
- Legacy fork remains in the original worktree with all uncommitted changes intact.
- Rust core/launcher/data compile on the clean baseline. Full Tauri build requires
  `apps/codex-plus-manager/dist`, which is absent until frontend dependencies are available.

## Target split

| Package | Responsibility |
| --- | --- |
| `xuan-workspace-search` | Official plugin manifest, MCP tool and Skill; bridge owns ripgrep/search safety |
| `xuan-usage` | Official plugin manifest, MCP tool and Skill; bridge owns provider adapters |
| `xuan-polish` | Official plugin manifest, MCP tool, Skill and thin Composer user script |
| `xuan-plus-remote` | Independent bridge adapter, HarmonyOS app, protocol 1.5 and cloud service |
| `xuan-bridge` | Versioned local JSON API, configuration migration and shared process boundary |

## Stages

1. **Stage 0 complete:** official baseline branch/worktree, build and rollback evidence.
2. **Stage 1 complete:** bridge protocol, plugin manifests, MCP/Skills and migration utility.
3. **Stage 2 complete:** workspace search implementation and filesystem contract tests.
4. **Stage 3 complete:** generic usage adapter and official-token-history integration boundary.
5. **Stage 4 complete:** OpenAI-compatible polish adapter, Composer script and DOM smoke test.
6. **Stage 5 in progress:** port `xuan-plus-remote` with protocol/database compatibility tests.
7. **Stage 6:** compatibility matrix, release packaging, parallel-run and rollback validation.

## Version policy

The official host, each plugin, `xuan-bridge` and `xuan-plus-remote` have
independent semantic versions. Compatibility is checked by automated manifest,
MCP, bridge JSON, migration and mobile protocol contract tests before a release.
