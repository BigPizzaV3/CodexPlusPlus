# Official CodexPlusPlus 1.3.0 Migration

## Baseline

- Branch: `codex/migrate-official-1.3.0`
- Official tag: `v1.3.0`, commit `be6a45852f9992a688f33be933f444ee098fc67a`
- Legacy fork remains in the original worktree with all uncommitted changes intact.
- Rust core/launcher/data compile on the clean baseline. Full Tauri build requires
  `apps/codex-plus-manager/dist`, which is absent until frontend dependencies are available.

## Target split

| Package | Responsibility |
| --- | --- |
| `xuan-workspace-search` | Official plugin manifest, MCP tool and Skill; bridge owns ripgrep/search safety |
| `xuan-usage` | Official plugin manifest, MCP tool and Skill; bridge owns provider adapters |
| `xuan-polish` | Official plugin manifest, MCP tool, Skill and thin Composer user script |
| `xuan-plus-remote` | Remote Bridge 1.0.0, HarmonyOS app 1.0.0, protocol 2.0-only cloud service and existing in-place deployment |
| `xuan-bridge` | Versioned local JSON API, configuration migration and shared process boundary |

## Verified extension fit

- Workspace search and provider usage fit the official Codex plugin manifest, MCP and Skill
  surfaces without a host-source change.
- Polish uses the same plugin/MCP surface; the optional Composer button is a thin official User
  Script and is protected by a DOM smoke test.
- Phone pairing, device identity, cloud WebSocket ownership and task synchronization do not fit a
  request-scoped plugin process. They remain an independent service. Only the renderer command ABI
  uses an official User Script.
- No migrated feature adds fields to official `settings.rs`, changes the official manager UI, or
  writes into `app.asar`.

## Stages

1. **Stage 0 complete:** official baseline branch/worktree and rollback evidence. Rust core,
   launcher and data compile; the full Tauri workspace remains blocked by the absent frontend `dist`.
2. **Stage 1 complete:** bridge protocol, independent JSON/SQLite storage, official marketplace,
   self-contained MCP packages, migration CLI and HTTP/MCP contracts.
3. **Stage 2 backend complete:** streaming workspace search, preview safety and MCP-to-ripgrep
   integration. The old injected Ctrl+Shift+F modal is intentionally not copied into official source.
4. **Stage 3 backend complete:** generic and OwlAI usage adapters read independent profiles.
   Official per-thread token history remains owned by the host's existing history implementation.
5. **Stage 4 backend complete:** Chat Completions, Responses and Anthropic polish adapters,
   context boundaries, thin Composer script and executable DOM smoke test.
6. **Stage 5 backend complete:** the independent desktop bridge now owns the migrated pairing,
   DPAPI identity, task sync, cloud transport and CDP adapters. A standalone User Script provides
   the official renderer command ABI. Signed-HAP and real-device acceptance remain open.
7. **Stage 6 release candidate complete:** compatibility matrix and real Codex CLI marketplace
   install passed; the cloud path uses one in-place 1.0.0/2.0/schema-8 release with pre-deploy
   backup and same-script rollback. Linux release-host and production cutover remain open.

## Version policy

The official host, each plugin, `xuan-bridge` and `xuan-plus-remote` have
independent semantic versions. Compatibility is checked by automated manifest,
MCP, bridge JSON, migration and mobile protocol contract tests before a release.
The operational cloud upgrade and rollback procedure is recorded in
`docs/migration/cloud-in-place-upgrade-and-rollback.md`.
