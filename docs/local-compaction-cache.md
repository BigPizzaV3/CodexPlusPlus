# 本地压缩缓存复用（实验）

在单个供应商的请求设置中启用“本地压缩缓存复用（实验）”，可尝试提高本地压缩请求的缓存命中概率。默认关闭，开关独立保存在每个供应商上。单模型路由可以在入口或实际目标供应商启用；聚合请求使用实际成员的设置。Responses API 与 Chat Completions 支持此实验，纯官方登录、聚合入口和 Anthropic Messages 不提供此开关。

用户实测表明，这种方式可以改善压缩请求的缓存命中概率，但不保证每次命中，也不保证将压缩提示放在上下文末尾不会影响摘要质量。建议结合供应商返回的缓存用量、费用和实际摘要内容判断是否保留。关闭后恢复普通本地压缩路径。

本地 Responses 压缩请求本来就将摘要提示放在历史末尾，但通常不携带普通请求中的工具声明。本实验只补回同一会话、供应商及模型最近一次成功普通请求的工具声明，同时设置 `tool_choice: "none"`、`parallel_tool_calls: false`，不允许摘要请求调用工具。历史、系统提示、末尾摘要提示、缓存 key、输出限制、推理设置和其他参数始终来自当前请求；不会拼入旧消息或旧系统提示。Chat Completions 使用对应协议的已转换声明，已有 exec 兼容转换继续保留。

这不等同于保证“上一条普通请求原封不动，只追加摘要提示”。如果客户端在本地压缩时修改了历史或系统提示，本实验不会为缓存覆盖这些内容。

代理只在内存中保存工具声明，不保存完整请求或会话内容。声明按供应商、凭据、协议、模型和会话隔离，不要求完整历史或系统提示匹配，也没有 15 分钟失效门槛；最多保留 128 组、合计 32 MiB，每组不超过 8 MiB，按最近使用顺序淘汰。最近成功普通请求不再提供工具时，旧声明会被清除。进程退出后声明清空，未记录到声明时直接使用当前原始压缩请求，不从磁盘读取会话或跨会话借用工具。

实验仅修改请求，不缓冲或验收摘要，不要求供应商 SSE 事件逐项一致，也不因摘要内容或 HTTP 400/422 自动重发原始压缩请求。响应解析、错误处理和供应商失败切换继续沿用现有代理流程。原生远程压缩不受此实验影响。工具声明缓存与供应商计费缓存相互独立；本实验减少请求前缀差异，不代表供应商一定命中缓存。

启用本实验后，本地摘要不进入普通请求自动重试功能的 SSE 预读、整段缓冲或流内失败重试分支，避免再次引入摘要校验重发。关闭实验时保留上游的本地摘要自动重试行为。普通请求的自动重试保持不变，缓冲模式也会记录可供下一次本地压缩复用的工具声明。传输失败、HTTP 错误处理、鉴权刷新和供应商失败切换仍沿用现有流程，因此不能将此实验理解为整个网络栈的全局单次发送保证。

此前的“搜索历史压缩兼容（实验）”已退役，相关服务端修复已合入 sub2api。旧配置中的 `webSearchHistoryCompat` 会被忽略，不会自动开启新实验，也不再为自定义供应商主动补入搜索工具声明。上游针对官方登录路径的自动兼容处理继续保留。已保存真实 `upstreamBaseUrl` 的本地代理配置会继续使用该真实上游，避免将代理自身当作供应商。

“前缀稳定层”是独立设置，其行为与本实验分开控制。
