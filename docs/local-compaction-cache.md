# 本地压缩缓存复用（实验）

本实验的支持范围仅限旧版直连供应商，暂不支持 Codex++ 2.0 网关。在旧版直连供应商的请求设置中启用“本地压缩缓存复用（实验）”，可尝试提高本地压缩请求的缓存命中概率。默认关闭，开关独立保存在每个供应商上。Responses API 与 Chat Completions 支持此实验，纯官方登录、聚合入口和 Anthropic Messages 不提供此开关。

2.0 网关供应商页不提供此开关，本 PR 不接入网关的多 Key 调度，也不承诺通过旧配置或手动写入字段启用网关请求时的缓存效果。网关调用与直连共用部分代理代码，不代表已经完成网关适配；后续如需支持，应单独验证供应商选择、会话身份与 Key 轮换。

本地缓存键保留 API Key 的哈希，不跨 Key 共享记录。即使供应商、模型和会话相同，切换 Key 后也不能补用上一把 Key 的上下文字段；如果切回此前使用过且记录尚未被淘汰的 Key，仍可能复用该 Key 自己的记录。轮询切换 Key 可能降低命中率；不通过移除 Key 哈希规避这一边界。上述本地记录与上游计费缓存是两层机制，供应商是否按 Key 或账号隔离计费缓存由其实现决定，本实验不作保证。

单模型路由可以在入口或实际目标供应商启用。入口的实验开关有效时，仅在这次请求的目标供应商副本上执行 OR 合并；入口关闭不会覆盖目标自身已开启的设置。此继承不保存配置，也不改变目标的凭据、协议和实际模型，缓存仍按实际目标隔离。聚合入口不传递此开关，聚合请求只使用实际成员的设置。

实测表明，这种方式可以改善压缩请求的缓存命中概率，但不保证每次命中，也不保证将压缩提示放在上下文末尾不会影响摘要质量。未命中供应商缓存时，补回的工具声明会增加摘要请求的输入 token 开销。建议结合供应商返回的缓存用量、费用和实际摘要内容判断是否保留。关闭后恢复普通本地压缩路径。

### 原生本地压缩兼容

原生本地 Responses 压缩请求本来就将摘要提示放在历史末尾，但通常不携带普通请求中的工具声明。本实验从同一会话、供应商及模型最近一次收到 HTTP 2xx 的普通请求中记录逻辑上下文字段；构造摘要请求时补回工具声明，以及当前请求缺失的系统提示、缓存相关字段、推理和文本设置等。当前请求明确提供的字段优先，包括空串、`null` 或空对象；不会为了旧缓存覆盖新的开发者规则或明确的摘要格式。

当前完整 `input` 以及末尾摘要提示始终保留，不从旧请求复制历史，不恢复旧 `previous_response_id`、conversation 状态、输出上限或本轮追踪信息。仅在实际补回非空工具声明时设置 `tool_choice: "none"`、`parallel_tool_calls: false`，要求上游在摘要阶段不调用工具；没有补回工具声明时保留当前请求的这两个字段。随后再进行 Chat Completions 或 Responses exec 兼容转换，确保最新工具结果也参与同一次转换。关闭实验时仍使用原生普通路径。

原生兼容路径不等同于保证“上一条普通请求原封不动，只追加摘要提示”。如果客户端已裁剪历史或明确更新系统提示，本实验不会猜测旧消息或撤销新指令。诊断事件 `reuse_context` 的 `contextFieldsMatch`、`historyPrefixMatches` 只报告结构化字段及旧历史前缀哈希是否一致；不匹配不会触发裁剪、摘要验收、候选失效或补发。这些诊断不是最终上游请求的完整前缀证明，也不代表供应商实际命中计费缓存。

代理仅在内存中保存上述上下文字段和历史前缀的条数/哈希，不保存旧 `input`、完整请求或响应正文，也不将这些字段写入诊断日志。记录按供应商、凭据、协议、模型和会话隔离，没有 15 分钟失效门槛；最多保留 128 组、合计 32 MiB，每组字段序列化大小不超过 8 MiB，按最近使用顺序淘汰。最近普通请求的快照替换旧快照，移除的字段不会从更老请求恢复；超限或没有上下文字段会清除旧记录。进程退出后记录清空，缺少记录时直接使用当前原始压缩请求，不从磁盘读取会话或跨会话借用上下文。

实验仅修改请求，不缓冲或验收摘要，不要求供应商 SSE 事件逐项一致，也不因摘要内容或 HTTP 400/422 自动重发原始压缩请求。部分上游可能忽略 `tool_choice: "none"`，仍返回工具调用；若响应没有摘要文本，客户端可能得到空摘要。此类 JSON 或 SSE 响应仍按现有代理流程交付，不执行该工具，也不补发摘要请求。响应解析、错误处理和供应商失败切换继续沿用现有代理流程。原生远程压缩不受此实验影响。本地上下文缓存与供应商计费缓存相互独立；本实验减少请求前缀差异，不代表供应商一定命中缓存，也不保证摘要质量。

启用本实验后，本地摘要不进入普通请求自动重试功能的 SSE 预读、整段缓冲或流内失败重试分支，避免再次引入摘要校验重发。关闭实验时保留上游的本地摘要自动重试行为。普通请求的自动重试保持不变，缓冲模式也会记录可供下一次本地压缩复用的工具声明。传输失败、HTTP 错误处理、鉴权刷新和供应商失败切换仍沿用现有流程，因此不能将此实验理解为整个网络栈的全局单次发送保证。

现有“搜索历史压缩兼容（实验）”及其 `webSearchHistoryCompat` 设置保持不变，与本实验独立控制，不会自动开启本地压缩缓存复用。两者同时开启时，搜索兼容仍可能根据历史中的搜索调用补入搜索工具声明，改变最终请求前缀；本实验不会绕过搜索修复，也不保证最终前缀一致或缓存命中。官方登录路径的自动搜索兼容处理同样保持原有行为。

“前缀稳定层”是独立设置，其行为与本实验分开控制。
