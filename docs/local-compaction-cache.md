# 本地压缩缓存复用（实验）

在单个供应商的请求设置中启用“本地压缩缓存复用（实验）”，可尝试提高本地压缩请求的缓存命中概率。默认关闭，开关独立保存在每个供应商上。单模型路由可以在入口或实际目标供应商启用；聚合请求使用实际成员的设置。Responses API 与 Chat Completions 支持此实验，纯官方登录、聚合入口和 Anthropic Messages 不提供此开关。

实测表明，这种方式可以改善压缩请求的缓存命中概率，但不保证每次命中，也不保证将压缩提示放在上下文末尾不会影响摘要质量。建议结合供应商返回的缓存用量、费用和实际摘要内容判断是否保留。关闭后恢复普通本地压缩路径。

### 完整当前请求直接压缩

核心接口 `build_local_compaction_request` 接收调用方提供的完整当前 Responses 请求，在 `input` 末尾追加一个用户角色的摘要提示。当前全部历史、系统提示、工具声明及生成参数保持原样，只设置 `tool_choice: "none"`、`parallel_tool_calls: false`。原 `client_metadata` 原样保留，不插入额外模式标记。构造接口不发送请求，也不替调用方获取历史；调用方必须先包含最新回复和工具结果，不能盲目复用上一条普通请求。

发送时使用 `open_local_compaction_request_with_settings`；它调用同一个构造接口，通过仅存在于本地调用栈的状态区别完整请求与原生压缩请求，不将模式写入上游 JSON 或请求头。实际供应商启用实验后，此路径跳过旧上下文缓存及普通请求的摘要流内重试。独立脚本可调用此生产入口，不需要先向真实上游发送普通请求填充缓存。

此路径不需要先发送普通请求来填充本地缓存，也不会借同会话旧缓存补回当前已删除的字段。它保留原工具声明但禁止摘要阶段执行工具；摘要响应仍由现有调用方处理，不增加一次模型验收，也不因摘要内容暗中再次压缩。构造接口本身不处理响应；调用方须按正常响应状态处理明确失败、断流和没有正文的情况，不能把它们当作成功摘要。

### 原生本地压缩兼容

原生本地 Responses 压缩请求本来就将摘要提示放在历史末尾，但通常不携带普通请求中的工具声明。本实验从同一会话、供应商及模型最近一次收到 HTTP 2xx 的普通请求中记录逻辑上下文字段；构造摘要请求时补回工具声明，以及当前请求缺失的系统提示、缓存相关字段、推理和文本设置等。当前请求明确提供的字段优先，包括空串、`null` 或空对象；不会为了旧缓存覆盖新的开发者规则或明确的摘要格式。

当前完整 `input` 以及末尾摘要提示始终保留，不从旧请求复制历史，不恢复旧 `previous_response_id`、conversation 状态、输出上限或本轮追踪信息。设置上述禁工具控制之后，才进行 Chat Completions 或 Responses exec 兼容转换，确保最新工具结果也参与同一次转换。关闭实验时仍使用原生普通路径。

原生兼容路径不等同于保证“上一条普通请求原封不动，只追加摘要提示”。如果客户端已裁剪历史或明确更新系统提示，本实验不会猜测旧消息或撤销新指令。诊断事件 `reuse_context` 的 `contextFieldsMatch`、`historyPrefixMatches` 只报告结构化字段及旧历史前缀哈希是否一致；不匹配不会触发裁剪、摘要验收、候选失效或补发。直接压缩接口与原生兼容路径的保证不同，不能把一次接口测试当作客户端全路径已经验收。

代理仅在内存中保存上述上下文字段和历史前缀的条数/哈希，不保存旧 `input`、完整请求或响应正文，也不将这些字段写入诊断日志。记录按供应商、凭据、协议、模型和会话隔离，没有 15 分钟失效门槛；最多保留 128 组、合计 32 MiB，每组字段序列化大小不超过 8 MiB，按最近使用顺序淘汰。最近普通请求的快照替换旧快照，移除的字段不会从更老请求恢复；超限或没有上下文字段会清除旧记录。进程退出后记录清空，缺少记录时直接使用当前原始压缩请求，不从磁盘读取会话或跨会话借用上下文。

实验仅修改请求，不缓冲或验收摘要，不要求供应商 SSE 事件逐项一致，也不因摘要内容或 HTTP 400/422 自动重发原始压缩请求。响应解析、错误处理和供应商失败切换继续沿用现有代理流程。原生远程压缩不受此实验影响。本地上下文缓存与供应商计费缓存相互独立；本实验减少请求前缀差异，不代表供应商一定命中缓存，也不保证摘要质量。

启用本实验后，本地摘要不进入普通请求自动重试功能的 SSE 预读、整段缓冲或流内失败重试分支，避免再次引入摘要校验重发。关闭实验时保留上游的本地摘要自动重试行为。普通请求的自动重试保持不变，缓冲模式也会记录可供下一次本地压缩复用的工具声明。传输失败、HTTP 错误处理、鉴权刷新和供应商失败切换仍沿用现有流程，因此不能将此实验理解为整个网络栈的全局单次发送保证。

此前的“搜索历史压缩兼容（实验）”已退役，相关服务端修复已合入 sub2api。旧配置中的 `webSearchHistoryCompat` 会被忽略，不会自动开启新实验，也不再为自定义供应商主动补入搜索工具声明。上游针对官方登录路径的自动兼容处理继续保留。已保存真实 `upstreamBaseUrl` 的本地代理配置会继续使用该真实上游，避免将代理自身当作供应商。

“前缀稳定层”是独立设置，其行为与本实验分开控制。
