# 会话索引修复的前端补载阶段

在 Codex 中，有时历史搜索能找到消息，但滚动到对应时间段却看不到内容，或只显示中间工作过程，缺少最终答复、文件改动或用时。一种已确认的情况是：原始记录和历史索引仍然完整，前端已经登记了轮次，却没有加载完整消息。已有用户输入、已有部分消息，甚至连续多个非空轮次，都不代表消息分页已经完成。

此功能只处理这种前端补载缺口，不修复丢失的原始文件、损坏的索引或尚未登记的历史页。

## 入口与触发

沿用「会话管理 → 修复会话索引」按钮，以及现有的自动索引检查流程和开关。没有额外的增强开关、按钮、报告页或常驻扫描任务。

原有索引检查成功且未中止后，向已经注入的 Codex 主窗口发出一次补载请求。自动检查保留现有启动后的首次执行、每次检查结束后间隔 30 分钟复查及激活已有实例的流程；手动按钮不依赖自动检查开关。读取或刷新修复报告不会触发补载。

只修复当前本机会话中已经登记的终态轮次，包括连续非空但分页未完成的轮次，不再要求前后有内容作为锚点。不会加载未登记的历史消息页或其他会话。没有现存页面或当前没有可安全补载的会话时跳过，不把请求留到之后打开其他会话时执行。

## 行为与边界

- 调用 Codex 原生的历史消息加载器，让其更新自身的前端状态；不伪造消息或直接修改 DOM 中的聊天正文。最终答复及文件改动来自原生消息，不通过猜测工作过程生成。
- 原生消息分页不更新轮次用时。对缺失的用时和开始、完成时间，以 `thread/turns/list` 的 `notLoaded` 模式查找轮次元数据，不请求消息正文；只有原生 ID 与终态一致时，才通过原生状态更新接口填入缺值。保留已有值（包括 0），不改轮次状态、消息、输入、分页游标或历史区段，不整体重建会话。
- 前端阶段不改写 rollout、SQLite、供应商或模型配置，不启动新轮次，不发送模型请求；原有索引修复的证据核验、备份和事务保护保持不变。
- 每次读取前后核验原生忙碌状态、管理器归属及历史代际。正在生成、存在未确认提交或已有历史加载进行中时让步；切换会话、隐藏窗口、管理器或历史代际变化、重新注入后停止后续补载。元数据更新还要求当前窗口持有原生 owner 角色，并在更新回调中重复核验。已经发出的读取由原生加载器完成。
- 串行读取单页，每次索引检查最多处理 32 个轮次，消息和元数据合计最多 128 次分页调用，其中元数据查找最多 64 页、每页 32 个轮次；超过 12 秒不再发起新读取。取消每轮四页的提前截断，只以原生 `hasLoadedOldest` 确认消息分页完成，不因用户输入或部分工作过程出现而停机。
- 触及预算仍未补齐、元数据读取不兼容或源记录没有对应时间值时，结果为部分完成，不伪造完整报告。后续再次使用原有修复入口时，非空缺页仍可继续处理；保留原生驱逐与重连边界。
- 读取失败或没有进展时结束本次请求，不安排定时重试；需要时可再次使用已有「修复会话索引」按钮。同一个请求去重，并发请求不排队，重新注入共享正在进行的读取。
- 原生结构无法识别、端口或主窗口归属不明确时安全跳过，不猜测内部接口或默认连接其他实例。
- 保留原有报告的消息恢复计数，不把前端分页读取数混入数据库修复数量。前端补载结果仅记录不含聊天内容的诊断状态，失败不反转已提交的索引修复。
- 仅适配主窗口中的本机会话；远端主机、活动悬浮层和快捷聊天不在此阶段范围内。

此功能是对已确认症状的有界恢复措施，不表示已经查明最初漏加载的触发原因。新增功能本身仍需在实际 Codex 页面中验收，包括切换会话、重新连接和重新启动后的行为。
