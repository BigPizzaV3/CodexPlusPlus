# 历史空轮次补载（实验）

在 Codex 中，有时历史搜索能找到消息，但滚动到对应时间段却看不到内容。一种已确认的情况是：原始记录和历史索引仍然完整，前端已经登记了轮次，却没有加载该轮次的消息；原生界面会跳过这些空轮次。

此功能只处理这种前端补载缺口，不修复丢失的原始文件、损坏的索引或尚未登记的历史页。

## 开启方式

在管理器的「Codex增强 → 常用增强 → 对话与输入」，或 Codex 应用内的 Codex++ 设置中，开启「历史空轮次补载（实验）」并保存。默认关闭，受增强总开关控制。

开启后，只检查当前本机会话中已经登记的历史轮次。只对同一历史区段内、前后已有内容的空轮次尝试补载；不会为了检查而读取其他会话或加载全部历史。

## 行为与边界

- 调用 Codex 原生的历史消息加载器，让其更新自身的前端状态；不伪造消息或直接修改 DOM 中的聊天正文。
- 不改写 rollout、SQLite、供应商或模型配置，不启动新轮次，不发送模型请求。
- 正在生成或已有历史加载进行中时让步；切换会话、隐藏窗口或关闭开关后不再发起新的补载。已经发出的原生读取由原生加载器完成。
- 串行读取单页，每次开启最多处理 32 个轮次，每轮最多读取 4 页；恢复用户输入或确认已到轮次最早消息即停止。大轮次可能只补回部分内容，其余保留原生分页。
- 同一轮次失败或没有进展最多 2 次，失败后至少等待 30 秒；切换会话、重新注入不会重置预算。达到上限时提示，可关闭再开启开关后重试。
- 当前原生结构无法识别时限次尝试并提示，不猜测内部接口。
- 仅适配主窗口中的本机会话；远端主机、活动悬浮层和快捷聊天不在本实验范围内。

此功能是对已确认症状的有界恢复措施，不表示已经查明最初漏加载的触发原因。新增功能本身仍需在实际 Codex 页面中验收，包括切换会话、重新连接和重新启动后的行为。
