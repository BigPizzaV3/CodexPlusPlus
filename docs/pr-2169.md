# PR #2169: Stop bridge reinjection resource growth

## Summary

- Add exponential backoff to repeated bridge reinjection.
- Close superseded bridge sessions without waiting for another socket message.
- Track `Page.addScriptToEvaluateOnNewDocument` identifiers and remove them when a
  bridge generation is replaced, a session exits, or installation fails partway.
- Keep compatibility with CDP responses that do not return an identifier.

## Verification

- `git diff --check`: passed.
- Deterministic Windows fault injection: 20 minutes / 240 watchdog ticks.
- Reproducible command: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File
  tools/issue-2169-windows-fault-injection.ps1`.
- Reinjection attempts: 8 at seconds `0,10,30,70,150,310,610,910`.
- Maximum active registered scripts: 1.
- Maximum active sockets: 1.
- Monotonic resource growth: false.
- Rust tests: not run because this Windows environment has no `cargo`, `rustc`, or
  `rustfmt`. Run before merge:

```powershell
cargo test -p codex-plus-core --test cdp_bridge
cargo test -p codex-plus-core launcher
```

## Risk

The cleanup uses the CDP identifier returned by Chromium and sends removal commands
without waiting for a response during shutdown. If a target is already gone, cleanup
is best-effort and the existing shutdown path is preserved. Responses without an
identifier remain behaviorally unchanged.
