# 本机结构化用量接口

`/usage/history` 默认关闭，需开启 `usageHistoryEnabled`。首次查询才创建索引，
没有查询约一分钟后释放；关闭设置等待正在进行的扫描结束。请求不能指定文件路径。
原始会话、配置和登录信息均不修改，不发起模型请求。

## 已提交快照

`/usage/history-committed` 是独立的只读入口，请求必须包含
`snapshot: "committed"`。旧版宿主不认识此路由，不会因此触发旧历史扫描。
它支持 `period`、`from`、`to`、`model`、`sessionId`、`search`，
以及成对的 `startAt` / `endAt` 毫秒时间戳和 `scopeSessionId`。
`period: "all"` 可以查询全部已提交日期；`turnId`、
`includeSessionCursors` 和 `includeActivity` 不能用于此入口。

成功读取的 `source` 为 `persistent-local-rollout`，`revision`、日期汇总和
状态来自同一数据库快照。创建索引或扫描在后台进行，首次尚未就绪、
功能关闭、存储失败或请求无效时返回 `status: "unavailable"`；
已有数据仍可在后台处理或存在覆盖缺口时以 `partial` 返回。
`countStatus`、`classificationStatus` 和 `coverage` 分别描述计数、
归类和覆盖，`scan` 记录后台扫描状态；未确认的覆盖不能当作零消费。

固定的历史估计可存于该 home 的 `usage-history/<home-id>/daily-historical-classification.json`，
仅供已提交快照的只读投影。文件最多 4 MiB，格式如下：

```json
{
  "version": 1,
  "cutoffMs": 1794326400000,
  "cutoffDay": "2026-11-11",
  "rules": [{
    "day": "2026-11-10",
    "session": "*",
    "model": "",
    "provider": "custom",
    "role": "main",
    "conflicts": 0,
    "estimatedModel": "model-a",
    "estimatedProvider": "provider-a",
    "reason": "历史估计依据"
  }]
}
```

截止日期和时间必须对应同一个本地午夜，规则日期必须早于截止日期；
截止时间不能位于未来。`day`、原始 `model`、`provider`、`role` 和
`conflicts` 均按索引原值精确匹配，`session` 可为会话 ID 或 `*`，
同组优先使用精确会话规则。模型和供应商估计至少有一项，只能补充
对应缺失或冲突的字段；`reason` 可选，供离线核对，不参与匹配。
估计不改写索引、计数或原有分类不完整状态，`breakdowns` 分别通过
`modelInferred` 和 `providerInferred` 标记。删除文件即可撤销；
`classificationRevision` 供客户端识别策略变化，策略错误通过
`historicalClassificationError` 报告，已提交的原始计数仍可读取。

超过 62 天的已提交事件行可分批压缩为按日精度。已完成、单一来源、
严格有序且全部过期的会话进一步封存来源观察，只留下最后累计基线、
读取游标和冻结的每日汇总；每批最多检查或删除 256 条。复杂来源及
混合新旧记录仍保留观察。查询涉及已压缩或封存日期时，
`coverage.precision` 为 `day`；若请求的时间范围并非完整本地日，
响应不返回该范围的计数，调用方应提示改用整日范围。最近 62 天仍可
按毫秒范围查询。封存后正常追加使用保留的累计基线；旧日迟到记录、
来源替换或需要重新归并的竞争来源使相关会话暂停，并通过
`coverage.sealedReview` 报告待核对状态。已提交数量继续可读，失败批次
不推进游标，不用剩余明细覆盖冻结汇总。
同时请求 `scopeSessionId` 时，`scopedUsage.coverage.precision` 单独描述
该会话及其子会话的精度：其他会话仅支持按日统计，不会挡住本会话仍
保留的精确时间查询；全局结果仍按全局精度处理。

索引采用 1 GiB 工作预算，包含数据库和事务日志预留空间；数据库页数
最多约占预算的三分之一，文件按需增长。该预算不包含旧库、备份及既有
供应商证据库。已使用页达到页数预算的 80% 时，`scan.storageNearLimit`
提示容量接近上限；写满或磁盘不足仍通过 `scan.storageError` 报告。
已使用页达到 90% 时提前维护旧工具索引，降至 75% 以下后退出压力状态；
最近七天的工具详情定位不会因容量压力提前回收。新索引使用增量空间回收，每次
最多回收 128 个空闲页；回收命令必须消费全部返回行。已超页预算的
可回收索引在安全日志空间足够时分批恢复，否则保留只读访问并暂停摄取。
旧格式转换也受预算限制，不能把真正空间不足解释为已自动修复。

复杂会话归并不再以 25,000 条作为固定门槛，按会话处理并沿用 64 MiB
工作内存估算；超预算回滚本批次，其他来源继续。后台每轮最多处理两个
归类窗口，读取相关会话的完整竞争证据；来源未读完、证据缺失或超限时
只延后相关窗口，不等待全目录完成。迟到证据无需新的用量记录即可触发
再次归类。分类、日分组和版本同事务更新，不改变 Token、次数或时间。

按需请求 `includeLegacySummary: true` 可在响应中另行返回旧摘要，
同一日期只能选一个来源，不得将旧摘要与宿主结果相加。旧摘要只适用于
完整本地日及全部会话。工具列表和详情分别使用 `/usage/executions`
和 `/usage/execution-detail`，详情只读取最近七天内仍存在的原始结果。
工具逐次时间索引保留当天及此前 59 个本地日，更早记录压缩为按日分类
次数。超过七天的普通工具名称不会通过活动汇总显示；技能和 MCP 的
名称与时间保留至逐次记录到期。

## 查询与响应

支持 `period`、`from`、`to`、`model`、`sessionId`、`turnId`、`search`。
`startAt` / `endAt` 为成对的毫秒时间戳，使用 `[startAt,endAt)` 半开区间。
`scopeSessionId` 仅统计明确的子智能体后代，普通 fork 不算子智能体。
`includeSessionCursors` 和 `includeActivity` 必须显式开启；
`activityPage` 每页至多 512 条，`activityRevision` 可避免重复传输未变活动。

响应为 `accountingVersion:2` 的结构化 `days`，包含模型、供应商和
`main/subagent/unknown` 分类、会话别名及父子关系、完整性和累计水位。
`countStatus` 和 `classificationStatus` 分别报告计数及分类状态；
当前 `coverage.daily` 固定为 `unknown`，不能把全局 `complete` 当作某一天
或某个会话已经完整覆盖的证明。证据缓存不可用时，仍会返回本次读取中
可观察到的计数并标记为 `partial`；计数冲突或缺少必要基线的事件不会
当作精确消费计入，调用方不能把部分结果视作完整总量。
本层替换基础读取器响应，不提供旧版的费用、价格和挂件展示字段；
上游鲸鱼挂件仍使用独立的读取器、设置和路由。
调用方必须按版本消费，不能把累计水位当作消费增量。

一次性迁移生成的 `daily-legacy-summary.json` 可保存在同一 home 的
`usage-history/<home-id>/` 目录。仅当请求显式指定
`includeLegacySummary: true` 且没有会话、模型、turn 或搜索过滤时，
响应才单独提供 `legacyDays`、`legacyCapturedAt` 和 `legacyStatus`。
旧摘要只覆盖全部会话的本地整日，并始终标记为部分覆盖，不能用于
部分日或当前会话查询，也不能与同日原生结果相加。日期范围由 `from`、
`to` 筛选；是否能用原生结果替换旧摘要取决于对应日期及作用域的覆盖证明。
旧摘要文件最多读取 8 MiB；格式错误或超限通过 `legacyStatus` 报告，
不影响已有原生计数。

同一会话所有分段参与汇总；共享观测去重，独立计数流分别计量。
缺少基线、计数冲突和损坏时间保持 `partial`，不把历史累计计入当前日期。
缓存输入是输入的子集，总量为输入加输出；`cachedKnown` /
`reasoningKnown` 为 false 时不能把缺失计数当作精确的零。
`accountingFingerprint` 和 `membershipFingerprint` 绑定事件与计数，
不能单独证明扫描完整或分类正确。

工具活动只保留已完成调用的成功、失败、退出状态及技能分类元数据，
不返回命令、真实路径、正文和完整调用参数。默认不返回活动。

## 资源与生命周期

支持活动和归档目录中的 `.jsonl` / `.jsonl.zst`，最近 365 个本地日期。
文件状态保留预算 64 MiB，每轮输入和解压预算各 4 MiB，单行上限 1 MiB。
预算是索引准入估算，不是整个进程的内存上限。
跳过无关长行，相关或不可辨认的长行保守标记不完整，并继续后续有效记录。
查询驱动扫描，每五秒最多刷新一次；同一快照有界缓存范围和会话聚合结果。
空闲计时器只释放内存，不扫描会话。
`scan.processing=true` 时可能仍返回上一快照，应等待本轮刷新完成。

派生证据与计数冲突保护保存在 Codex++ 设置目录的
`usage-history/<home-id>/usage-provider-cache.sqlite`，不同 Codex home 分开。
原生 SQLite 日志尊重显式的 `CODEX_SQLITE_HOME`，不能退回另一实例目录。
缓存不可用时保守报告完整性，不能把缺失事件解释为零消费。

## 归属证据

事件自身明确归属优先。请求日志、实际 HTTP 完成日志必须按会话、时间、
模型和完整计数核验，双向不唯一、冲突或失败的请求保持未知。
模型命名空间与当前供应商选择都不能证明历史账单归属。
实时通知允许完成日志晚到至多一秒，但请求必须在通知前开始；
完整计数、双向唯一性、顺序、竞争撤销和持久化重验仍保留。
归属修复不会产生新用量。

普通请求按通知前 30 秒回看。只有带 `finalResponseEvidence: "final-response-v1"`
的单个成功最终响应，才允许通知前最多 120 秒的延迟补认，并支持已验证的重试。
该标记由本机响应链路提供；没有标记时仍要求单次、无自动重试的请求。
通知之后的完成日志仍最多晚一秒，请求必须在通知前开始。
延迟组合、无标记记录和模型冲突仍占用竞争证据，不会因自身不符合补认条件而被忽略；
只有完整计数和双向唯一性均成立时才补认，保存的证明在重读时重新验证。

`liveReceipts` 每批至多 128 条。查询按回执的会话及匹配时间窗读取已有请求缓存，
无需等待历史事件再次进入待补证扫描。别名、拒绝身份和保留边界来自同一只读事务，
不创建、迁移或清理数据库，也不持久化查询中新发现的冲突。
同一会话有回执的竞争窗口被行数上限或保留边界截断时，该批该会话不发出精确证明；
缓存与当前日志重复的同一请求只匹配一次，内容不一致仍拒绝。

设置目录既有 `usage-provider-evidence.json` 可提供版本 1 的事件绑定补证，
最多 32 MiB / 100,000 条。事件 ID、会话、时间、角色和计数均需匹配；
精确上游证据可补缺失模型，用户分类不能补模型或进入实时精确证明。
来源通过 `providerSource` / `providerEvidence.sources` 保留。
导入是本地只读消费，不写原始日志；删除文件后下一轮撤销补证。

## 按需供应商采集

首次查询才运行有界采集器，开启设置或启动管理器本身不采集。
它跟随索引生命周期，空闲、关闭或切换 home 时先停止采集，再等待在途扫描结束。
同一 home 使用状态目录单写者锁；不同 home 独立保存证据。
每批行数、请求日志尾部和原生日志 ID 窗口都有上限。

采集尊重打开文件身份、轮转、缺口和配置版本；
设置或网关供应商配置变化后重新绑定，配置无效时清除旧绑定并重试。
它不发送模型请求，不保存 API Key、请求头、正文或完整端点 URL。
