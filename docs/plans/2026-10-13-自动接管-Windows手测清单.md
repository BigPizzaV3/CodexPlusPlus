# 自动接管 · Windows 虚拟机自测清单

日期：2026-10-13
对象：Parallels「Windows 11」（Windows 11 ARM64，build 26200）+ 官方 Codex MSIX 26.1002.7124.0

## 我已经在虚拟机里做完的部分

- [x] 安装官方 Codex（`OpenAI.Codex_26.1002.7124.0_arm64`，SHA256 与镜像站公布值一致 `bfd70e3c…`）
- [x] 装 Rust（1.99.0）
- [x] 从 Mac 交叉编译出 **Windows x64 版 Codex++**（`cargo xwin` + 便携 LLVM + 静态 CRT）
- [x] **判据层真机实测通过**（用无 GUI 的探针程序 `takeover_probe.exe`）：

| 场景 | 实测结果 |
| --- | --- |
| 用户自己双击（裸启动，无调试端口） | `cdp_ready=false` / `other_instance=false` → **takeover** ✅ |
| Codex++ 带参数启动后（有调试端口） | `cdp_ready=true` → **wait(already_attached)** ✅ |
| 官方 App 未运行 | `NotRunning` → **wait(app_not_running)** ✅ |

- [x] 三条 Windows 关键行为已实测并写进代码注释：
  1. **应用激活（AUMID）不会把参数送达已运行实例** → 必须先结束再带参重开
  2. **`taskkill /T`（不带 `/F`）杀不掉 GUI 应用**（11 个进程一个没退）→ 优雅退出改用 `WM_CLOSE`
  3. **renderer / gpu / utility / crashpad 与主进程同名同路径**，还会继承调试端口 → 判据必须按 `--type=` 排除

## 需要在带桌面的会话里自测的部分

`prlctl exec` 的上下文没有桌面（实测连 notepad 都拿不到窗口句柄、explorer 未运行），
所以 Tauri 界面与完整接管链路要在虚拟机窗口里手动跑。

### 准备

1. 打开 Parallels 的「Windows 11」窗口，正常登录桌面。
2. 我在 `C:\cptest\` 留了：
   - `CodexPlusPlus.exe`（Windows x64 版，已静态链接 CRT，可直接双击）
   - `takeover_probe.exe`（判据探针，命令行调试用）
3. 打开自动接管开关（默认关闭）：在 `C:\Users\mac\.codex-session-delete\settings.json` 里加一行
   （注意用**无 BOM** 的 UTF-8 保存，PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会带 BOM 导致读不出）：

```json
{
  "codexAppAutoTakeover": true,
  "codexAppAutoTakeoverWhenActive": "immediate"
}
```

### 用例

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 双击 `C:\cptest\CodexPlusPlus.exe` | 出现 Codex++ 窗口/托盘图标，日志文件 `C:\Users\mac\.codex-session-delete\codex-plus.log` 出现 `takeover.supervisor_started` |
| 2 | 关闭 Codex++ 窗口（回托盘），退出官方 Codex | — |
| 3 | 双击官方 Codex 图标 | 数秒内被接管：任务管理器里 `ChatGPT.exe` 命令行带 `--remote-debugging-port`，日志出现 `takeover.restart_requested` → `takeover.ready` |
| 4 | 再从「安装维护」页关掉开关，重启官方 Codex | 不再自动接管（日志无新的 `takeover.restart_requested`） |
| 5 | 打开开关，在官方 Codex 里做个耗时任务，中途手动退出官方 Codex 再打开 | `defer` 策略下应等到不忙才接管；点「立即接管」可强制 |
| 6 | 官方 Codex 已在运行（带我们的端口）时点「立即接管」 | 返回「已经被接管了」，不重启 |

### 看日志

```powershell
Get-Content "$env:USERPROFILE\.codex-session-delete\codex-plus.log" | Select-String takeover | Select-Object -Last 20
```

关键事件：`takeover.probe_decision`（决策与原因）、`takeover.restart_requested`（真重启）、
`takeover.attach_requested` / `takeover.attached`（只附着、不动窗口）、
`takeover.exit_result`（退出结果，含 `forced`）、`takeover.degraded`（失败原因）。

## 已知限制

- **Codex++ 没运行时不会接管**（守护线程在管理器进程里）。要开机就管，需要把 Codex++ 加进启动项。
- Windows 侧的**优雅退出**依赖 `WM_CLOSE`；如果官方 Codex 不响应，会退化为 `taskkill /F /T`（可能丢未落盘状态），日志里 `takeover.exit_result` 的 `forced=true` 就是这条路径。
- 虚拟机里有快照 `before-codexplus-testing`，需要回滚可以用。
